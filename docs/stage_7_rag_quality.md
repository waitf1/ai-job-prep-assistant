# 第七阶段：RAG 质量基线与验证

## 目标

第七阶段不增加新的业务功能，而是提高已有 RAG 资料库检索的可靠性和可解释性。

此前系统会把检索工具返回的所有片段直接传入后续分析。现在系统会保留原始召回结果，并过滤距离过大的低相关片段，只将有效片段作为个人经历证据传入 Prompt。

## 检索处理流程

```text
模型决定调用资料库检索
-> Chroma 返回原始片段及距离
-> 规则排除非正文与超距离候选
-> AI 结合 JD 与完整简历挑选项目证据
-> 有效片段进入后续分析
-> 无有效片段时使用降级说明，不注入无关资料
```

## 当前实现

### 距离过滤

在 `app/rag/vector_store.py` 中定义：

```text
DEFAULT_MAX_RETRIEVAL_DISTANCE = 0.8
```

Chroma 返回的距离越小，代表查询与资料片段越相关。当前规则为：

- 距离小于或等于 `0.8`：进入下一步自动选片；
- 距离大于 `0.8`：视为低相关并过滤；
- 距离未知：保留，以兼容旧数据或不返回距离的检索实现。

该值是当前 embedding 模型和个人资料场景下的初始基线，不代表所有数据都适用。后续应通过真实资料和测试样例继续校准。

### 结构感知切片与自动选片

为避免固定字符数切片混合不同主题，系统现在优先识别 Markdown 标题、PDF 页码、中文章节标题和段落空行。单段内容过长时，会优先按句末标点切分，再退回字符长度切分。

每个片段都会保存所属章节标题，用于改善 embedding 上下文，并在页面中展示。

系统不再要求用户设置 `top_k`，而是：

1. 统一召回最多 10 个候选片段；
2. 过滤超过 `0.8` 的低相关片段；
3. 将通过规则过滤的候选、岗位要求和完整简历交给 AI，挑选 0–5 个能补充岗位匹配判断的项目证据；
4. AI 可以返回空结果，不会为了凑数量使用弱相关片段；
5. 如果 AI 重排序失败，回退为原有的距离断层规则：当候选与前一个候选距离差达到 `0.25` 时停止采用后续片段，最终自动采用 0–5 个片段。

这能结合“语义相关性”和“该片段是否能为当前简历、JD 提供新增证据”进行判断，避免为了凑固定数量而把相对弱的候选片段带入后续 Prompt。

### 资料库重建要求

新切片策略不会自动修改已经存入 Chroma 的旧片段。如需使用新策略，请在侧边栏清空资料库，然后重新上传原始文件并建立资料库。系统只会提示，不会自动删除已有资料。

### 原始召回与有效片段

工作流结果同时保存：

- 原始召回片段；
- 实际采用的有效片段；
- 被过滤片段数量；
- 因相关性断层未采用的片段数量；
- AI 重排序未采用的片段与选择理由；
- AI 重排序失败时的规则回退状态；
- 当前阈值；
- 检索状态与说明。

因此，系统可以区分：

- 模型没有请求检索；
- 模型请求检索但没有返回结果；
- 模型请求检索，但结果均因低相关被过滤；
- 模型请求检索，并实际采用了相关资料。

### 降级行为

若模型决定检索，但所有片段都被过滤，后续的能力匹配、简历建议和面试题生成仍会执行。

区别在于：系统会传递“未检索到足够相关资料”的说明，而不会把被过滤的无关内容放入 Prompt，从而避免无关内容误导模型。

## 页面变化

RAG 模式的“Step 2：RAG 检索”现在会展示：

- 原始召回数量；
- 实际采用数量；
- 被过滤数量；
- AI 相关性复核的选择理由与失败回退状态；
- AI 判断为无需采用的候选内容；
- 当前最大距离阈值；
- 每个有效片段的章节、来源、编号和距离；
- 被过滤片段及其过滤原因；
- 全部过滤或未返回结果时的明确提示。

## 自动化验证

新增 `tests/test_rag_quality.py`，覆盖：

- 阈值内片段保留；
- 超过阈值片段过滤；
- 距离未知时兼容保留；
- 空检索结果。
- Markdown 标题与 PDF 页码的章节切片；
- 超长段落的句子优先切分；
- 距离断层截断和最多采用 5 个片段的规则。

同时扩展 `tests/test_model_driven_tool_calling.py`，覆盖：

- 模型触发检索后，只有有效片段进入工作流上下文；
- 全部片段被过滤时，工作流进入正确降级状态；
- 原有普通模式和模型跳过检索行为保持不变。

## 当前边界

本阶段仍未实现：

- 混合检索；
- 多 query 检索；
- 自动动态调整阈值；
- 检索结果不足时的二次检索。

这些应在积累更多真实资料、建立稳定评测样例后再考虑。

## 简历库与项目资料库分离

阶段七补强后，资料不再全部混入同一个向量库：

- 简历库保存多份完整简历，并用独立文档级向量索引按岗位 JD 自动选择一份；
- 用户也可以手动指定本次使用的简历；
- 选中后，整份简历进入岗位匹配、简历建议和面试题生成，不再依赖局部召回；
- 项目资料库只保存项目报告、项目说明等补充证据，项目库为空时仍可只依据完整简历完成分析。

项目资料入库前采用混合清洗：

1. 本地规则排除空白、分隔线、页码、重复页眉页脚、目录点线和乱码；
2. 识别参考文献、致谢、版权/原创声明等非正文区段；
3. 所有通过规则清洗的候选片段每 5 个组成一个批次，由 AI 一次返回带索引的受限 JSON 分类，避免逐片段串行调用；页面会显示当前审核批次进度；
4. 模型必须覆盖批次内全部片段；结果缺失、重复或格式错误时，仅该批次保守保留，避免误删正文；
5. 检索时再次按内容类型和文本特征排除旧库噪音。

### 分类重建要求

旧混合资料库无法可靠自动判断某个文件是简历还是项目报告，因此不会自动迁移或删除。升级后需要：

1. 将简历重新上传至“简历库”；
2. 清空新的“项目资料库”后，仅上传项目报告和项目经历资料；
3. 通过页面清洗统计检查规则删除、区段排除和 AI 复核结果。

## 面试表达

```text
我在 RAG 检索链路中增加了检索质量控制：入库前先用规则清洗确定性噪音，再以批量 AI 复核语义价值；检索后结合距离过滤和 AI 重排序，只将真正能补充岗位匹配的项目证据注入 Prompt。若没有足够相关资料或 AI 调用失败，系统会明确降级或回退，而不是使用无关内容。
```
