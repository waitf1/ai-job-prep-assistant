# 第二阶段：文档解析说明

## 目标

第二阶段将第一阶段的手动复制粘贴升级为文件上传解析：

```text
上传简历 / 项目资料 + 上传岗位 JD -> 自动解析文本 -> 人工检查与编辑 -> 调用大模型分析
```

本阶段仍不引入 RAG。上传文件解析出的文本会直接进入当前岗位匹配分析流程。

## 已支持文件类型

- PDF：使用 PyMuPDF；
- docx：使用 python-docx；
- txt：支持 utf-8-sig、utf-8、gbk；
- md / markdown：按文本文件解析。

## 新增模块

```text
app/services/document_parser.py
```

核心能力：

- `parse_document(file_name, file_bytes)`：根据文件后缀自动选择解析方式；
- `ParsedDocument`：保存文件名、文件类型和解析文本；
- `DocumentParseError`：封装文档解析失败原因。

## 页面变化

`app/main.py` 现在包含两个上传入口：

- 上传简历 / 项目资料；
- 上传岗位 JD。

上传成功后，解析文本会自动填入页面文本框。用户仍然可以手动修改解析结果，再点击“开始分析”。

这种设计有两个好处：

- 避免 PDF / Word 解析结果错误时直接送入模型；
- 保留人工校对入口，便于提升分析质量。

## 当前边界

本阶段只做基础文本提取，不处理：

- 扫描版 PDF OCR；
- 图片中的文字；
- 复杂表格结构还原；
- 多文件合并知识库；
- 向量检索和引用来源。

这些能力会在后续 RAG 阶段继续完善。

## 验收标准

本阶段完成后，需要确认：

- 上传 PDF 后能提取可读文本；
- 上传 docx 后能提取段落和简单表格文本；
- 上传 txt / md 后能正确读取中文；
- 解析结果会显示在文本框中并允许编辑；
- 点击“开始分析”后仍能正常调用 OneAPI；
- 文档解析失败时页面能给出明确错误。

## 下一阶段方向

文档解析完成后，第三阶段进入 RAG：

```text
多份个人资料 -> 文本切分 -> embedding -> Chroma 向量库 -> 检索相关片段 -> 大模型分析
```

第三阶段的重点是让模型基于检索到的个人资料证据回答，而不是把整篇文档一次性塞进 Prompt。
