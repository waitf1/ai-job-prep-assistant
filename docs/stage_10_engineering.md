# 阶段十：工程质量与证据核查

状态：基础工程改进已实现；真实效果评测延期。当前仅有一份个人简历，不报告准确率或效果提升。

## 已实现

- JSON 顶层必须为对象，列表成员必须为字符串；反馈分数必须为 0–100 整数，关键反馈字段缺失时报错。
- 检索规划仅接受一次指定工具调用，校验 query 类型。JSON 规划中的字符串 false 不会触发检索。
- LLM_TIMEOUT_SECONDS（默认 60 秒）、LLM_MAX_RETRIES（默认 2）、LLM_MAX_INPUT_CHARS（默认 100000）可在 .env 中配置。
- 超时是 SDK 单次请求配置，含重试的一次操作总耗时可能更长。输入预算按字符计数，并非精确 token；超长输入请求发送前拒绝。
- 终端输出 llm_call JSON：调用 ID、模型、系统 Prompt 指纹、字符数、耗时、成功状态、异常类型、输入与输出 token。供应商未返回用量时为 null。
- 不记录 Prompt 正文、回答、密钥、URL 或异常消息；仅在进程内保留最近 200 条指标。token 是成功响应的供应商报告，不含未知失败请求用量；没有推算价格、实际重试次数或质量评分。
- 循环面试发给模型的历史为最近 8 轮，每轮问题/回答/反馈限长 1000/3000/1000 字符；页面完整原始记录不截断。
- 复盘覆盖全程限长摘录，超过 50 轮均匀抽样；页面说明这一限制。摘要不是全量逐字审阅。
- 匹配结果支持 point_index/source/quote 引用，程序核对原文存在与位置；引用不匹配时显示警告，不把文字存在等同于推理正确。
- 引用字段可为空以兼容旧模型响应，页面明确提醒；尚未强制每个结论必须有引用。
- 历史兼容旧版本。为避免复制简历正文，简历引用仅在当前分析显示；历史仅保存项目引用，读取历史时重新核对项目原文。

## 如何验证

运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v`。
新增测试使用合成字符串与模型替身，检查无效输出、工具白名单、输入限额、日志脱敏、长历史预算和引用匹配，不是模型效果评测。
启动应用后，正常分析即可在终端看到 llm_call 指标。不同 Prompt 指纹可帮助区分调用，尚未实现完整工作流 trace 或指标仪表盘。
