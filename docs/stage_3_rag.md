# 第三阶段：RAG 个人资料库说明

## 目标

第三阶段将系统从“把全部文本直接交给大模型”升级为“先检索个人资料，再基于检索结果分析”。

核心流程：

```text
上传个人资料
-> 文档解析
-> 文本切分
-> embedding 向量化
-> 存入 Chroma
-> 用岗位 JD 检索相关片段
-> 将检索片段加入 Prompt
-> 大模型生成岗位匹配分析
```

## 为什么需要 RAG

直接把简历和岗位 JD 发给大模型有几个问题：

- 文档一多，Prompt 会变长，成本和响应时间上升；
- 模型容易忽略长文本中的细节；
- 模型可能编造简历中没有的经历；
- 后续加入项目报告、课程报告等资料后，不能每次都把所有文件塞进上下文。

RAG 的作用是让系统先从个人资料库里找出与当前岗位最相关的片段，再交给大模型分析。

这样大模型负责理解和表达，向量检索负责提供上下文证据。

## 当前实现

新增模块：

```text
app/rag/
├── __init__.py
├── chunking.py       # 文本切分
└── vector_store.py   # Chroma 向量库封装
```

### 文本切分

`split_text` 会将长文本切成较短 chunk。

当前默认参数：

- chunk_size：700 字符；
- overlap：120 字符。

保留 overlap 的原因是避免关键语义刚好被切在两个片段之间。

### 向量化

当前默认 embedding 模型：

```text
BAAI/bge-small-zh-v1.5
```

该模型由 `sentence-transformers` 加载，用于将中文文本转换为向量。

首次运行时可能需要下载模型，因此“建立资料库”可能会比较慢。

### 向量数据库

当前使用 Chroma 持久化保存向量。

默认保存目录：

```text
data/vector_store
```

每个入库片段会保存：

- 片段文本；
- 来源文件名；
- 文件类型；
- chunk 编号。

## 页面功能

页面侧边栏新增：

- 分析模式切换（普通分析模式 / RAG 资料库模式）；
- 上传入库资料；
- 建立资料库；
- 追加资料库；
- 清空资料库；
- 检索片段数量 top_k。

当前版本还补充了以下交互：

- 资料库为空时仅可“建立资料库”，资料库非空时仅可“追加资料库”；
- 按文档内容去重，重复资料会跳过并展示文件名；
- 可查看资料库中的已存片段内容；
- 当前选择 RAG 模式时，会自动使用资料库检索，不再额外提供单独勾选项。

两种模式的区别：

- 普通分析模式：直接基于页面中的“简历内容 + 岗位 JD”进行分析；
- RAG 资料库模式：页面不再要求填写完整简历，而是优先从资料库中检索相关片段，仅保留“岗位 JD + 可选补充说明”。

分析时，如果 RAG 资料库不为空，系统会用岗位 JD 检索相关片段，并把这些片段加入 Prompt。

分析完成后，页面会展示“本次 RAG 检索片段”，便于检查模型依据。

## 当前边界

当前版本仍然是最小可用 RAG，不处理：

- 多用户资料隔离；
- 高级 rerank；
- 混合检索；
- OCR；
- 大规模文档管理；
- 检索质量评测。

这些可以作为后续优化点。

## 当前已知待优化项

以下问题不影响当前第三阶段核心验收，但需要在后续工程优化阶段补齐：

- 还没有为资料库去重、重建、片段查看等关键行为补充自动化测试；
- 目前主要依赖手动验证、`compileall` 和 lint 检查进行回归；
- 后续应增加最小化单元测试或集成测试，降低功能迭代时的回归风险。

## 验收标准

本阶段需要验证：

- 上传 txt / md / pdf 后可以成功入库；
- 资料库能生成文本片段；
- 使用岗位 JD 能检索出相关个人经历；
- 分析结果能参考检索片段；
- 页面能展示本次检索到的片段；
- 资料库可以清空并重新构建。

## 面试表达

可以这样解释本阶段：

```text
我在项目中实现了一个本地 RAG 个人资料库。系统会先将简历、项目报告等文档解析成文本，再切分为 chunk，并使用 bge-small-zh-v1.5 生成 embedding 存入 Chroma。用户输入岗位 JD 后，系统会先检索最相关的个人经历片段，再将这些片段作为上下文交给大模型生成岗位匹配分析，从而减少模型胡编，并提升回答与个人经历的相关性。
```

## 下一阶段方向

下一阶段可以做 Agent 工作流，将当前一次性分析拆成多个步骤：

```text
JD 解析
-> RAG 检索
-> 能力匹配
-> 简历建议
-> 面试题生成
```

建议先做固定流程工作流，而不是一开始就实现完全自主决策的复杂 Agent。

这样可以让系统的分析过程更可控，也更容易展示中间结果。
