# 第九阶段：结果保存与历史复盘

状态：已实现。更新日期：2026-09-09。

## 页面使用

1. 完成岗位分析后，点击“保存本次分析”。修改页面输入不会改写已生成结果的 JD；再次保存同一次分析只更新同一条历史。
2. 完成面试复盘后，点击“保存本次复盘”。独立面试可直接保存；如果关联的岗位分析已经保存，会同时记录关联关系。
3. 从左侧进入“历史记录”，首页列表按记录类型和创建时间（全部、最近 7/30/90 天）筛选。悬停摘要可预览，点击右侧“查看详情”进入标签页详情；筛选和详情在切页后保留。
4. 历史分析展示 JD、能力匹配、简历建议、面试准备、已采用项目证据、检索统计与工具执行状态。历史复盘展示总结及每轮问题、原始回答、来源、评分和完整反馈。
5. 在详情页点击“删除此记录”，在弹窗中点击“确认删除”。删除分析只解除关联，已经保存的面试复盘继续保留。

未点击保存的分析、未保存的复盘和进行中的面试仍只存在于当前页面会话。刷新或重启不能恢复未保存内容；已保存内容可重新打开历史查看。

## 从历史分析再次面试

- 在记录列表进入一份岗位分析详情，点击“去模拟面试”，会跳转并预选该历史记录；也可直接在模拟面试页选择“通过岗位分析结果进行面试”，再勾选一份历史分析。
- 在模拟面试页配置题目来源、轮数与替换简历，再点击“开始模拟面试”。不重新调用岗位分析工作流；首题、逐轮评价和新复盘仍调用模型。当前会话分析也能从分析页跳转后直接使用。
- 理论题使用历史岗位 JD，没有 JD 时拒绝准备。题库题必须有当前上传的有效题库，不从历史中恢复未使用题目。
- 项目题默认核对原简历库引用和 SHA-256 正文指纹；简历一致时读取全文。临时简历、已删除简历或变化后的简历都不能自动用于历史项目面试。
- 此时可“选择简历库”或“重新上传或输入”，勾选确认后继续；相同正文可复用旧匹配与证据，正文变化时清除旧匹配、旧项目证据和预生成问题，仅依据新简历和原岗位要求出题。
- 真正点击开始时重新读取历史与简历，避免准备后简历被删除或变更。查看历史本身不要求原简历仍存在。

## 存储与边界

- 数据库：`data/history.sqlite3`，使用 Python 标准库 sqlite3，无新增依赖。
- 数据库版本为 `PRAGMA user_version = 1`，内容快照 `schema_version = 1`；不支持的版本会报错，不覆盖文件。
- 每次分析和面试使用独立稳定 ID；重复保存更新已有记录，保留创建时间并更新修改时间。
- 时间以 UTC 保存。面试通过可空的外键关联分析，删除使用 `ON DELETE SET NULL`。
- 只保存明确选择的结构化字段，不保存 API Key、客户端、环境变量、session_state、上传原文件或完整简历副本。分析与面试文本可能包含个人经历摘要和原始回答。
- 保存已采用的项目片段及其来源；未采用候选全文、原始模型 JSON、原始工具输入/输出/错误不保存。历史工具详情仅保留名称和成功状态，因此不是完整调试日志归档。
- 题库全文不持久化；已经问过的问题作为面试记录的一部分保存。
- 固定面试的 `max_rounds` 为 1–10；循环模式为 JSON null。旧 3–5 轮记录仍可读取，数据库和快照版本无需迁移。
- 早期未接入的 `app/storage/history_store.py` 与可能存在的 `data/app_history.sqlite3` 保留原状，不自动迁移。新界面只使用 `history_repository.py` 和新数据库。
- 历史删除不会调用简历库或向量库的删除/重建。数据库锁定、损坏或不可写时保留页面结果并提示重试，不自动清理或替换数据。

## 实现与验证

- `app/storage/history_repository.py`：版本初始化、保存、列表/筛选、详情、删除及外键事务。
- `app/storage/history_snapshots.py`：分析与复盘快照、字段白名单及恢复。
- `app/services/history_interview.py`：真实简历恢复、指纹核对和题源校验。
- `app/ui/history_panel.py`：历史列表、详情、删除和再次面试入口；复用现有结果视图。
- `tests/test_history_store.py`、`test_history_snapshots.py`、`test_history_interview.py`、`test_history_ui.py`：持久化、隔离、恢复与页面回归。

运行完整验证：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

测试使用临时 SQLite 数据库、模拟简历库和模拟 LLM，覆盖应用会话重建后的读取、重复保存、关联删除、简历缺失与变化、再次面试、保存失败重试，以及当前 RAG 结果和历史详情跨页查看时互不覆盖。不使用或删除真实用户资料。

当前不实现跨重启续答未完成面试、旧库自动迁移、题库持久化、用户账号、云同步或统计看板。
